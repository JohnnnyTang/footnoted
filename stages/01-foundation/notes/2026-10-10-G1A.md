## (c) Coverage storage → **spans + `cell_stats`, with a read rule** (D-014)

Raw driver, cipher on, desktop / emulator:

| Metric | A per-cell rows | B spans + `cell_stats` |
| --- | ---: | ---: |
| Database size | 265.4 MiB | **30.0 MiB** |
| Full 5-year insert | 95.2 s / 70.5 s | **2.4 s / 3.4 s** |
| Delete the 1,033 km leg | 1.13 s / 0.92 s | 1.34 s / 1.30 s |
| Densest z10 tile, L20 | 521 / 473 ms | spans 1,693 / 1,455 ms · **`cell_stats` 40.6 / 51.5 ms** |
| Densest z10 tile, L16 | 638 / 545 ms | **`cell_rollups` 0.15 / 0.17 ms** |

Two sessions independently found the same trap. Repeated commutes give Mexico City 318 k per-segment spans, so reading fog from `coverage_spans` is slow: 1.2–1.7 s per tile in S01-20a1's bench, and a 4.8–6.2 s wait for one fog update per pass in S01-20a2's emulator pan. **The ruling therefore carries a read rule:** fog and statistics read `cell_stats` and `cell_rollups` only. The spans are the provenance and write model (invariant 6). F01.4 (G1-B) must follow it (S01-V022, S01-V028).
